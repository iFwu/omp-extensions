# Contributing

Keep changes focused on the existing portable extensions. Do not add personal provider configuration, credentials, session data, or host-specific paths.

Submit changes and [issues](https://git.nice.do/fwu/omp-extensions/issues) to the canonical [Forgejo repository](https://git.nice.do/fwu/omp-extensions). Clone with `git clone https://git.nice.do/fwu/omp-extensions.git`. GitHub is a downstream Git mirror synchronized every 24 hours, independently of commits and releases on Forgejo.

Use OMP 18.16.0 standalone, Bun 1.4.4, Python 3.12, and npm. Validate only against the current pinned OMP release; do not add compatibility branches or tests for older releases. Follow the README setup, then run `bun run typecheck`, each affected workspace's tests (`bun run --filter @ifwu/omp-<feature> test`), and relevant package smoke (`bun run smoke:package --workspace <feature>`; repeat the option for multiple workspaces). Selected smoke always includes the root suite. Run `bun run test:integration` for cross-feature lifecycle, shared fixture, or registration changes. For suite-wide dependency or packaging changes, run all workspace tests (`bun run test:workspaces`), integration, and unfiltered `bun run smoke:package`; `bun run test` remains the full local test command. Workflow-only edits need syntax and command-contract validation plus relevant package smoke, not every runtime test locally. Commit the single `bun.lock` when dependency changes require it. Never update the supported host version without exercising its real UI integration.

Keep each feature's implementation and tests in its workspace. Cross-feature behavior belongs in `tests/integration`; reusable test-only process/configuration helpers belong in `test_support`. Do not create shared runtime packages without actual cross-feature reuse. Preserve the persisted `dotfiles.ask-history` message type. Grouping state/render modules are internal helpers, not extension entry points. Do not duplicate extension registration.

Pull requests should explain the observable change, compatibility implications, and checks actually executed (including skips). Add focused regression coverage and update the changelog for user-visible changes. Time-threshold TUI fixtures use `test_support.write_grouping_clock` or `write_next_step_clock` to control only the extension's time/deadline dependency; keep actual OMP events, requests, cancellation, state transitions, and rendering. Advance simulated time instead of sleeping for minutes. Do not mock expected results, shorten production thresholds, or patch global clocks/timers; host I/O and failure deadlines remain real. Drain PTY output while waiting for a terminated fixture process to exit so shutdown rendering cannot block on a full terminal buffer.

All workspace packages and the root suite use one version and release tag. Update their manifests together, pass the affected local tests, typecheck, and relevant smoke, then tag that exact commit and push the commit and tag to Forgejo. Preserve existing tags; the hosting migration retains version `0.8.0`. Full CI completion is not a prerequisite for tagging or publishing after affected local checks pass. The retained `.github/workflows/verify.yml` describes the GitHub-copy Linux/macOS matrix; Forgejo automation requires provisioned runners and a separately validated workflow. Until that is available, run the applicable local checks and report their results explicitly. Workspace tests, integration, and typecheck/package smoke remain independent verification slices, with no per-workspace typecheck or build. Keep any CI failures visible for investigation. The root manifest explicitly lists feature entry points; merely adding a workspace does not make OMP load it. Validate affected standalone payloads as well as the suite, and document installation without implying npm publication.

Report bugs in the [Forgejo issue tracker](https://git.nice.do/fwu/omp-extensions/issues) with versions, OS, the failing test or reproduction, and redacted stderr. Never include production tokens, provider endpoints, or private conversations.
