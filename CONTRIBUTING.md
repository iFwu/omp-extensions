# Contributing

Keep changes focused on the existing portable extensions. Do not add personal provider configuration, credentials, session data, or host-specific paths.

Use OMP 18.12.6 standalone, Bun 1.4.4, Python 3.12, and npm. Follow the README setup, then run `bun run typecheck`, each affected workspace's tests (`bun run --filter @ifwu/omp-<feature> test`), and relevant package smoke (`bun run smoke:package --workspace <feature>`; repeat the option for multiple workspaces). Selected smoke always includes the root suite. Run `bun run test:integration` for cross-feature lifecycle, shared fixture, or registration changes. For suite-wide dependency or packaging changes, run all workspace tests (`bun run test:workspaces`), integration, and unfiltered `bun run smoke:package`; `bun run test` remains the full local test command. Workflow-only edits need syntax and command-contract validation plus relevant package smoke, not every runtime test locally. Commit the single `bun.lock` when dependency changes require it. Never update the supported host version without exercising its real UI integration.

Keep each feature's implementation and tests in its workspace. Cross-feature behavior belongs in `tests/integration`; reusable test-only process/configuration helpers belong in `test_support`. Do not create shared runtime packages without actual cross-feature reuse. Preserve persisted identifiers (`dotfiles/claude-context`, `dotfiles.ask-history`). Grouping state/render modules are internal helpers, not extension entry points. Do not duplicate extension registration.

Pull requests should explain the observable change, compatibility implications, and checks actually executed (including skips). Add focused regression coverage and update the changelog for user-visible changes. The TUI suite intentionally includes long-running scenarios; do not replace real-runtime assertions with mocks or shorten their behavioral boundaries.

All workspace packages and the root suite use one version and release tag. Update their manifests together, pass the affected local tests, typecheck, and relevant smoke, then tag that exact commit. Push it to `main` to start the full Linux/macOS verification asynchronously; completion of that matrix is not a prerequisite for tagging or publishing. Pull requests and manual dispatches also run the full matrix. Workspace tests, integration, and typecheck/package smoke are independent slices on each OS, with no per-workspace typecheck or build. CI failures remain visible, do not cancel other slices, and are not silently retried or suppressed; report them for investigation. Only superseded runs of the same event/ref are cancelled. The root manifest explicitly lists feature entry points; merely adding a workspace does not make OMP load it. Validate affected standalone payloads as well as the suite, and document installation without implying npm publication.

Report bugs with versions, OS, the failing test or reproduction, and redacted stderr. Never include production tokens, provider endpoints, or private conversations.
